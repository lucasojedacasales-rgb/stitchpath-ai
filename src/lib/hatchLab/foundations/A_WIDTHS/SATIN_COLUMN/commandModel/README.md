# P1.F1 — straight satin lab command model

`P1.F1-A_WIDTHS-STRAIGHT-SATIN-LAB-COMMAND-MODEL-V1`

Turns the closed experimental geometry (paired boundary zigzag, mm) into a **local, measurable
sequence of stitch moves**. Laboratory only: `candidateOnly: true`, `integrated: false`,
`machineReady: false`, `exportReady: false`. Nothing here is a productive command, a machine command
or an export format — see `productiveCommandContractAudit.md`.

## Modules

| file | responsibility |

| `buildLabSatinCandidate.js` | read-only adapter: measurement + fixture identity → candidate envelope |
| `compileStraightSatinCandidateToLabCommands.js` | pure compiler with hard preconditions |
| `measureLabSatinCommands.js` | metrics + safety diagnostics (never repairs) |

| `canonicalizeLabSatinCommands.js` | canonical form + `commandModelHash` |
| `fixtures/` | one persisted model per real case, generated by the API |
| `reports/` | `commandModelReport.json` / `.md` |

## Path and segment classification

Geometry order is `L0 → R0 → L1 → R1 → …`. One command per consecutive point pair; even commands are
`cross_column` (both rails of one station), odd commands are `advance_diagonal` (right rail → next
station's left rail). With N stations: `crossColumn = N`, `advanceDiagonal = N − 1`,
`total = 2N − 1 = pointCount − 1`. Points are never added, removed, reordered, rounded or quantized.

## startAnchor policy

`startAnchorMm` is exactly `pointsMm[0]`. It is **not** turned into a jump, a stitch from `[0, 0]`, a
trim or a tie-in: the model is local to one column and knows nothing about the previous region. Entry
and exit moves are a sequencing decision that belongs to a future adapter.

## Length policy

Audit window `0.3 mm … 12.1 mm`, taken from the baseline `machineSettings` (not Hatch parameters, not
a learned rule). Each command reports `belowMinimum`, `aboveMaximum`, `zeroLength`, `finite`; the
model reports `splitRequired` and `shortStitchHandlingRequired`. **No** autoSplit, **no** short-stitch
filtering, **no** merging, **no** deletion — diagnostics only. A model is declared complete only when
zero-length, non-finite, above-maximum and below-minimum counts are all `0`.

## Forbidden ops

`jump`, `trim`, `color_change`, `stop`, `end`, `tie_in`, `tie_off`, `needle_up`, `needle_down`,
`underlay`, `compensation`, `export`, `machine_code`. Their presence makes validation **fail**; they
are never silently removed. Their absence is deliberate: the model represents only the local stitch
path of a single column, with no inter-object sequencing.

## Hash procedure

`commandModelHash = fnv1a32(canonicalStringify(envelope))` with `commandModelHash`, `generatedAt`,
`fixturePath` and `fixtureSha256` removed, keys sorted at every depth, commands in canonical field
order and numbers unrounded. No variable timestamp is inside the hashed part.

## Not answered by P1.F1

Pipeline insertion, application to a productive region, DST/DSB generation, underlay, compensation,
autoSplit and Final Look wiring. Next authorized step:
`PROCEED_TO_P1_F2_ISOLATED_PRODUCTIVE_COMMAND_ADAPTER`.

## P1.F2 implementation

`productiveAdapter/` implements only that authorized next step. It targets the read-only audited
absolute-mm command core `{ type, x, y, regionId }` and maps `toMm` without rounding or
quantization. `startAnchorMm` remains separate with `requiresExternalSequencing: true`.

The adapter deliberately excludes color, `stitchType`, productive `source`, `layerType`, generic
metadata, and control commands because P1.F1 cannot supply them authoritatively. See
`productiveAdapter/productiveCommandContractAudit.md` and
`productiveAdapter/reports/productiveAdapterReport.md`.

P1.F2 is still isolated and not machine-ready. Its next recommendation is
`PROCEED_TO_P1_F3_SHADOW_PRODUCTIVE_COMMAND_VALIDATION`; P1.F3 is not implemented here.
